# Architecture — Disney World Park Pulse

Last updated: 2026-10-19. Describes the accepted main implementation merged through PR #2 at 738ec44d8067d3d2e80a4f44899e379bcf2b0b44. The owner reports a clean live check after merge. See [PROJECT_STATUS.md](PROJECT_STATUS.md) for the current source, evidence and known limitations.

## System overview
The browser receives static HTML, CSS, JavaScript and images from GitHub Pages (or a local development server). JavaScript requests public read APIs from two Cloudflare Workers. The Workers collect external data and share a D1 database. The frontend does not connect directly to D1.

    Static host / local HTTP server
           |
           v
    Browser: index.html + assets + images
           |                         |
           v                         v
    Queue/history Worker       Weather Worker
           |                         |
           +----- shared D1 DB ------+

The repository also has a separate Python static-data collector. It is not a drop-in replacement for the Worker APIs.

## APIs and response contracts
Queue origin: https://wdw-queue-probe.jacocksr.workers.dev
Weather endpoint: https://park-pulse-weather.jacocksr.workers.dev/api/weather

| Route | Main contract | Worker cache TTL |
|---|---|---|
| /api/live-wait-times | updated_at; parks[key] with metadata, crowd_score, hours and rides | 60 seconds |
| /api/history-24h | updated_at; rides[id].points as [ISO timestamp, wait]; optional hours metadata | 120 seconds |
| /api/historical-summary | rides[id].buckets[weekday_hour] averages/samples; recent summaries; daily_heatmap | 900 seconds |
| /api/ride-history?ride=ID | ride; days[YYYY-MM-DD] with [epoch seconds, wait] points; up to 14 archived days | 600 seconds |
| /api/closure-events | schema_version 1; tracking/coverage metadata; event IDs, sampled transitions, category/state/uncertainty | 120 seconds |
| Weather /api/weather | schema_version 1; parks with observations, forecasts, alerts, collection success/errors and freshness | 60 seconds |

Cache timestamps and successful HTTP responses do not guarantee fresh source observations. Preserve source timestamps and stale/unavailable states.

## Data semantics to preserve
- Eastern park-calendar dates and weekday/hour buckets; display-time selection is distinct.
- Live snapshot, rolling history and archived day points have different timestamp representations.
- Effective card averages use positive finite numeric waits from qualifying open standard attractions.
- Matched comparisons average matched attractions equally, track eligible/matched counts and gate on summed historical samples. They are not sample-weighted park averages.
- Backend crowd score uses positive waits and an absolute mean-wait formula (mean / 7, rounded and clamped 1–10). It is distinct from matched percent-versus-typical; UI wording/band discrepancies remain separate issues from the fixed banner branch bug.
- Zero wait, missing observation and reported closure are different states. Different views intentionally have different inclusion rules.
- Closure times are sampled bounds, not exact transitions or causes. Keep unknown starts, interrupted observation, refurbishments and scheduled experiences distinct.
- Park marker groups use the hour of each event's first closed report. Counts of dots, distinct rides, episodes and currently reported closed rides are not interchangeable.
- Reported Open time is the ride feed's last_updated timestamp, formatted through the selected display zone, NOT the current time or an inferred reopening time. Missing/stale source data must not appear current.
- Maintained event descriptions/dates do not establish live ticket inventory or showtimes.

## Closure interaction and motion
- Main average-waits chart and park-wide popup each keep their own inline-panel state, scoped to park/day.
- The full-width disclosure provides keyboard/touch access independent of dot visibility.
- Marker selection opens that panel filtered to an hour; nearest marker is chosen when hit regions overlap. Show all today clears the filter.
- Multiple episodes expand per ride; history links retain the standard ride popup and individual shading controls.
- Red outer frames denote interruption context; neutral interiors remain distinguishable. Current-state open badges remain green and closed badges red.
- The park popup keeps a visible header/close button, scrolls only its body and uses compact mobile metrics.
- Zero-padding wrappers animate height and opacity: approximately 320ms opening, 260ms closing. Rapid reversal, nested resizing and same-scope re-render resumption are handled in 90-closure-history.js.
- Closing content is inert; focus returns to its disclosure. Reduced Motion skips nonessential animation.
- Marker-triggered reveal waits for opening; scrolling is targeted to the modal body where applicable.
- Time-zone changes refresh closure labels/panels without additional data fetching. Do not add network work to a presentation transition.
